# OpenCode Visual Control v0.2.0 — Multi-monitor + window management

This is an experimental, Windows-only release. Coordinate/DPI behavior has unit coverage on Linux but **still needs a real Windows multi-display + mixed-DPI smoke test**.

## Changes

- **Physical-pixel virtual desktop:** `computer_displays` returns the `virtual` rectangle and monitor rectangles, with IDs such as `\\.\DISPLAY1`. Coordinates are **absolute physical pixels**; secondaries left/above the primary may have negative x/y. Pointers cannot move into gaps between monitors.
- **Whole desktop or selected monitor:** `computer_screenshot(max_width=1600, monitor_id="all")` returns a PNG for the entire virtual desktop, or only the named monitor. `computer_screenshot` still requires the user's local RESUME permission.
- **DPI awareness:** Host enables Per-Monitor-V2 DPI awareness before importing PyAutoGUI or creating the Tk overlay, with fallback to Per-Monitor/System DPI awareness. This aims to prevent coordinate virtualization at 125–175% scaling, but mixed-DPI layouts require real-world testing.
- **Window discovery:** `computer_windows(limit=80)` lists visible titled windows with HWND, title, PID and native bounds; it requires RESUME because titles may be private.
- **Window focus:** `computer_focus_window(hwnd)` restores/focuses a selected visible window. Respect Windows focus restrictions: this tool intentionally does not bypass them, UAC, secure desktop, or higher-integrity windows.
- **Click visual and bar movement:** Win32 `SetWindowPos` positions overlay windows using absolute screen coordinates, allowing the indicator to appear on displays with negative origins.
- **Preserves v0.1.1:** Unicode typing via `SendInput`, click-through indicators, PAUSE/RESUME, global Esc, local-only token gate.

## Agent usage

1. `visual_computer_computer_status` — verify host is online, paused/enabled.
2. `visual_computer_computer_displays` — read monitor IDs, virtual desktop rect, physical resolution.
3. If PAUSED, ask the human to click RESUME. Never resume via automation.
4. `visual_computer_computer_screenshot(monitor_id="all")` or target one monitor.
5. To convert a position seen in a *resized* screenshot to a physical-pixel coordinate:

   `x_physical = origin.left + round(x_in_image * source_rect.width / image_width)`

   `y_physical = origin.top + round(y_in_image * source_rect.height / image_height)`

   `origin`/`source_rect` are from `computer_displays`: virtual for `all`, selected monitor for a monitor id. Never click using unconverted, resized screenshot coordinates.
6. Use `computer_move`, `computer_click`, `computer_drag` and `computer_scroll` with **absolute** physical x/y; negatives are valid.
7. For app switching, `computer_windows` then `computer_focus_window(hwnd)` (do not blindly activate windows with unexpected titles).
8. Verify effects with a fresh screenshot. Respect Esc/PAUSE; stop and ask before sensitive/irreversible actions.

## Limits & privacy

- The host starts PAUSED; all screenshot, window-title and control operations are blocked until the user presses RESUME locally. Monitor geometry and status remain readable while paused.
- Only the interactive unlocked session is controlled; UAC, secure desktop and elevated windows are out of scope.
- Screenshot and window-title data can be forwarded by OpenCode to the chosen model provider once the user grants access.
- Windows may deny `SetForegroundWindow` and that failure is surfaced rather than bypassed.
- Multi-monitor hotplug during screenshot may cause a safe retry error if the topology and screenshot size differ.
- Automated tests are not substitutes for physical Windows integration testing, especially heterogeneous DPI and displays located at negative x/y.
